# From two polynomials to a 26,000-line circuit

**What this document is for.** It explains, with the maths, how the gross code memory circuit follows from the two
polynomials $A = x^3 + y + y^2$ and $B = y^3 + x + x^2$. The notebook `gross_code_from_polynomials.ipynb` runs each step, and
`bbcode.py` holds the code. Nothing here depends on a QEC library: numpy does the arithmetic and Stim holds and simulates the circuit.

---

## 1. A file versus a program

IBM's gross code memory circuit (12 rounds, $p = 0.004$) is a Stim file of 26,411 lines, one gate per line. It is the
*output* of a program. The program behind it is short because the code is regular: every check looks the same, shifted
across a grid. Writing that program means understanding five things:

1. the grid and its moves (the meaning of $x$ and $y$),
2. how the polynomials give the check matrices,
3. how many logical qubits there are, and which operators they are,
4. how a check becomes gates, and in which order,
5. how the measurement results become detectors and observables.

## 2. The torus and its moves

Take a grid of $l \times m$ cells ($12 \times 6 = 72$ for the gross code) whose edges wrap around. Number cell $(i, j)$ as
$c = mi + j$. Define two moves:

$$x : (i, j) \mapsto (i + 1 \bmod l,\ j), \qquad y : (i, j) \mapsto (i,\ j + 1 \bmod m).$$

A monomial $x^a y^b$ is "$a$ steps in the first direction and $b$ in the second". Each move is a permutation of the 72 cells
and can be written as a $72 \times 72$ permutation matrix $S$ with $S_{c, \sigma(c)} = 1$. Three facts carry everything
that follows:

- $x^l = 1$ and $y^m = 1$ (going all the way round returns you to the start),
- $xy = yx$ (the order of two moves does not matter),
- $(x^a y^b)^\top = x^{-a} y^{-b}$ (the transpose of a permutation matrix is its inverse).

So the matrices generated by $x$ and $y$ behave exactly like polynomials in two commuting variables with
$x^{12} = y^6 = 1$ and coefficients in $\{0, 1\}$ with $1 + 1 = 0$. In algebra this is the ring
$\mathbb{F}_2[x, y] / (x^l - 1,\ y^m - 1)$. In code, a move is a list `perm` of 72 numbers (`bbcode.shift`).

## 3. Check matrices

A polynomial with three terms is a sum of three permutation matrices: a $72 \times 72$ matrix with three 1s per row and per
column. The code has 144 data qubits, two per cell (called L and R), and 72 X and 72 Z checks, one of each per cell. Bravyi et
al. define

$$H_X = [\,A \mid B\,], \qquad H_Z = [\,B^\top \mid A^\top\,].$$

Reading row $c$: the X check in cell $c$ touches the L qubits $\sigma_{A_1}(c), \sigma_{A_2}(c), \sigma_{A_3}(c)$ and the R
qubits $\sigma_{B_1}(c), \sigma_{B_2}(c), \sigma_{B_3}(c)$. Every check has weight 6 and every data qubit is in 3 X and 3 Z
checks.

**Why the checks commute.** An X check and a Z check can both be measured only if they overlap on an even number of qubits.
For all pairs at once this is

$$H_X H_Z^\top = A B + B A = 2AB = 0 \pmod 2,$$

using $AB = BA$. This holds for *any* two polynomials, which is why the family is easy to search.

## 4. How many logical qubits

Each independent X check and each independent Z check removes one qubit's worth of freedom:

$$k = n - \operatorname{rank}_{\mathbb{F}_2} H_X - \operatorname{rank}_{\mathbb{F}_2} H_Z.$$

The rank is computed by Gaussian elimination with XOR as addition (`gf2_rank`). For the gross code
$\operatorname{rank} H_X = \operatorname{rank} H_Z = 66$, so $k = 144 - 132 = 12$. On the same grid, $A = 1 + x$, $B = 1 + y$
gives the toric code, with ranks 71 and $k = 2$.

So 6 of the 72 X checks are products of the others (and likewise for Z). All 72 are still measured: removing 6 would break the
fact that every cell looks the same, which is what makes the circuit regular. The redundant checks also give the decoder extra
consistency information.

## 5. Logical operators

A logical $Z$ operator is a vector $v \in \mathbb{F}_2^{144}$ (a $Z$ on each qubit where $v = 1$) that

- commutes with every X check: $H_X v = 0$, and
- is not a product of Z checks: $v \notin \operatorname{rowspace}(H_Z)$.

`logical_z` computes a basis of $\ker H_X$ (by row reduction: every free column gives one basis vector) and keeps vectors that
raise the rank of $[H_Z;\ \text{kept}]$, until it has $k = 12$. Logical $X$ operators come from $\ker H_Z$ outside
$\operatorname{rowspace}(H_X)$. The two sets pair up: the $12 \times 12$ matrix $L_X L_Z^\top$ has full rank, so every logical
qubit has an X and a Z operator acting on it. Their weights are at least 12, the distance.

## 6. The Tanner graph, and why a term is a layer of gates

The Tanner graph has a node per data qubit and per check, and an edge wherever a check touches a qubit. On the torus, each X
check has six edges: two to neighbouring cells (terms $y$ and $x$, as in a toric code) and four that reach 2–3 cells away
($x^3$, $y^2$, $y^3$, $x^2$).

One term, say $y$, is a permutation. "Every X check does a CNOT with the L qubit it reaches through $y$" pairs each of the 72
X checks with a different L qubit. No qubit appears twice, so all 72 CNOTs can run in the same time step. **Each polynomial
term is one clash-free layer of 72 CNOTs.** That is the single fact that turns the code into a short program.

## 7. Measuring a check

| | X check (stabilizer $X^{\otimes 6}$) | Z check (stabilizer $Z^{\otimes 6}$) |
|---|---|---|
| prepare the check qubit | $\lvert +\rangle$ (`RX`) | $\lvert 0\rangle$ (`R`) |
| entangle | CNOT, check qubit → each data qubit | CNOT, each data qubit → check qubit |
| measure | in the X basis (`MX`) | in the Z basis (`M`) |

For the Z check, each CNOT adds the data qubit's bit to the check qubit, so the check qubit ends holding the parity of its six
data qubits. The X check is the same with the roles of X and Z exchanged.

## 8. Schedules

With six layers per check type, a round could simply run all six X layers, measure X, then all six Z layers and measure Z.
That is the **simple schedule**: 14 time steps, always correct. In each CNOT layer, though, only half of the qubits are busy.
The other half wait, and waiting costs noise.

Interleaving X and Z layers shortens the round, but there is a rule. Consider an X check $a$ and a Z check $b$ sharing the data
qubits $Q_{ab}$ (an even number, since they commute). For each shared qubit, either $a$'s CNOT acts first or $b$'s does.
Exchanging the order of the two CNOTs on one qubit commutes $X$ past $Z$ once and introduces a sign. The pair is measured
correctly only if

$$\bigl|\{\, q \in Q_{ab} : t_X(a, q) < t_Z(b, q) \,\}\bigr| \equiv 0 \pmod 2$$

for every pair $(a, b)$. Otherwise the outcomes are randomised and the detectors fire even without noise.
`schedule_conflicts` counts the pairs that break this rule. Bravyi et al.'s order passes for all 5,184 pairs; swapping two of
its Z steps breaks it for 216 pairs.

**The depth-8 schedule** (Bravyi et al.). Writing $A_1, A_2, A_3 = x^3, y, y^2$ and $B_1, B_2, B_3 = y^3, x, x^2$:

| step | X checks | Z checks |
|---|---|---|
| 1 | prepare | CX via $A_1$ from R data |
| 2 | CX via $A_2$ to L data | CX via $A_3$ from R data |
| 3 | CX via $B_2$ to R data | CX via $B_1$ from L data |
| 4 | CX via $B_1$ to R data | CX via $B_2$ from L data |
| 5 | CX via $B_3$ to R data | CX via $B_3$ from L data |
| 6 | CX via $A_1$ to L data | CX via $A_2$ from R data |
| 7 | CX via $A_3$ to L data | measure |
| 8 | measure | reset (for the next round) |

In steps 2–6 every one of the 288 qubits is in a CNOT. This order was taken from the circuit `stabilizer-qec` generates for the
gross code; after renumbering qubits, our circuit has the same gates in the same time steps.

## 9. Detectors and observables

A **detector** is a set of measurements whose parity is fixed when there is no noise. For a Z-basis memory:

- **round 1:** each Z check alone ($\lvert 0 \ldots 0\rangle$ is a $+1$ eigenstate of every Z check); X checks are random in round 1,
- **rounds 2 to $r$:** each check XORed with its own value one round earlier,
- **end:** all data qubits are measured; each Z check is rebuilt as the parity of its six data results and compared with its last
  measured value.

An **observable** is the parity of the final data results over the support of one logical $Z$ operator. With $r = 12$:
$72 + 11 \times 144 + 72 = 1{,}728$ detectors in total, of which $72 \times 13 = 936$ involve Z checks only. Those 936 are what a
Z-memory decoder uses, and they are exactly the ones IBM's `filter_detectors_by_basis` keeps.

## 10. Noise

Uniform circuit noise with one parameter $p$ (Bravyi et al.; IBM's `uniform_circuit` files):

- after each CNOT: two-qubit depolarising noise with probability $p$,
- after each reset: a flip ($X$ after `R`, $Z$ after `RX`) with probability $p$,
- each measurement result flipped with probability $p$,
- every qubit idle during a time step: single-qubit depolarising noise with probability $p$.

The last item is why the schedule matters so much. The simple schedule has 19,008 idle locations over 12 rounds; the depth-8
one has 3,456 (IBM's file: 3,312).

## 11. The decoder's input, and a trap

Stim converts the noisy circuit into a **detector error model**: a list of independent faults, each with a probability, the
detectors it flips and the observables it flips. Faults with identical effects should be merged into one entry with combined
probability $p_1 + p_2 - 2 p_1 p_2$.

When the circuit contains a `REPEAT` block, Stim 1.16 does not merge all of them: for the 12-round gross circuit it lists
11,160 faults instead of 8,784 (2,376 duplicates). BP-based decoders then treat the copies as independent possibilities and do
worse: with BP-OSD at $p = 0.004$, on the same 2,000 shots, failures went from 3.1% (flattened) to 7.3% (with `REPEAT`). So
`bbcode.detector_error_model` flattens the circuit before asking Stim for the model. Matching decoders such as PyMatching merge
parallel edges themselves and are not affected in the same way.

| check | result |
